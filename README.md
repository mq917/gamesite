# Two-Player Arena / Игра на двоих

Сайт для игры вдвоём: без регистрации, подбор соперника противоположного пола
близкого возраста, 4 игры (шахматы, шашки, крестики-нолики 5×5, морской бой), личный чат с соперником, общий чат для всех, счётчики онлайн. Интерфейс трёхъязычный (английский по умолчанию, переключатель EN/RU/AZ в
шапке, выбор сохраняется в браузере). Вся игровая логика — на фронтенде (в браузере), сервер только сводит
пары и пересылает сообщения. Никакие данные никуда не сохраняются: ни на диск,
ни в базу данных — всё живёт в оперативной памяти процесса, пока открыта вкладка.

## Языки

Переключатель EN/RU/AZ — кнопка в правом верхнем углу. Весь интерфейс (лобби,
модалки, чат, названия игр) переведён через `public/js/i18n.js`. Статусные
подсказки внутри самой игры (например «твой ход» / «your turn») тоже переведены
для всех игр; при переключении языка прямо посреди партии переводится всё,
кроме уже отрисованных подписей на самой доске (например «Твоё поле» в морском
бое) — это косметическое ограничение, играть не мешает.

## Структура проекта

```
gamesite/
  server/
    server.js       — весь бэкенд в одном файле (Node.js + ws)
    package.json
  public/
    index.html       — разметка (модалки, лобби, комната игры)
    css/style.css     — вся стилистика, тёмная/светлая тема
    js/app.js          — подключение, лобби, матчмейкинг, чат
    js/games/*.js       — 4 независимых игровых модуля
```

## Как это работает

1. Игрок вводит никнейм, пол и возраст (хранится только в вкладке браузера).
2. Выбирает игру (шахматы, шашки, крестики-нолики 5×5, морской бой) → попадает в очередь ожидания.
3. Сервер ищет в очереди игрока того же game, противоположного пола, с разницей
   в возрасте не больше текущего допуска (±2, увеличивается на 2 каждые 15
   секунд ожидания, до ±20).
4. Обоим показывается карточка друг друга — нужно **обоюдное согласие** («Играть!»),
   иначе (при отказе) сервер запоминает эту пару только в рамках соединения —
   как только вкладка закрывается, все ограничения слетают.
5. После согласия — комната: доска игры + чат. Все ходы и сообщения идут
   через WebSocket, сервер их не понимает и не проверяет, просто пересылает
   второму игроку.

## Запуск локально

```bash
cd server
npm install
npm start
# сайт на http://localhost:3000
```

Откройте два разных браузера/вкладки в режиме инкогнито, чтобы получить два
независимых сеанса и проверить матчмейкинг.

## Деплой в продакшен (бесплатные варианты)

Любой хостинг, поддерживающий длительные Node.js-процессы с WebSocket
(учтите — не подходят чисто статические хостинги вроде GitHub Pages).

### Render.com (проще всего)
1. Залейте папку `gamesite` в свой GitHub-репозиторий.
2. На render.com → New → **Web Service** (не Static Site! — сайту нужен живой
   Node-процесс с WebSocket, статический хостинг не подойдёт) → выберите репозиторий.
3. **Root Directory: `server`** (именно здесь лежит `package.json` — если оставить
   корень репозитория, Render не найдёт зависимости и деплой не поднимется).
4. Build Command: `npm install`. Start Command: `npm start`.
5. Render сам пробросит `PORT` — сервер уже читает `process.env.PORT` и слушает
   `0.0.0.0` (это важно: если слушать только `127.0.0.1`, прокси Render не
   достучится до контейнера, и страница будет вечно висеть на
   «Application loading…» — сервер в логах пишет, что запустился, а снаружи
   недоступен).

**Если после этих шагов всё равно виснет на загрузке:**
- Откройте вкладку **Logs** в дашборде Render — если там `Server listening on
  0.0.0.0:XXXX`, значит сервер стартовал нормально и дело не в биндинге.
- Бесплатный тариф Render «усыпляет» сервис после ~15 минут простоя; первый
  запрос после сна может грузиться до ~50 секунд — это нормально, не баг.
- Проверьте в настройках сервиса, что тип именно **Web Service**, а не
  **Static Site** — их легко перепутать при создании.
- Убедитесь, что Root Directory = `server`, иначе Build Command упадёт с
  «package.json not found» ещё на этапе сборки (видно в Logs).

### Railway.app / Fly.io
Аналогично: указываете `server` как корень сборки, команда старта `npm start`.

### Свой VPS
```bash
cd server && npm install
PORT=443 node server.js   # или через pm2 / systemd, за nginx с проксированием WS
```
Не забудьте настроить HTTPS/WSS (например через nginx + certbot), иначе
браузер на HTTPS-странице откажется открывать `ws://` соединение.

## Реклама

Место под баннер — просто `<div class="ad-slot">` сбоку от доски и снизу
страницы (`index.html`). Подключите туда код своей рекламной сети (например
Google AdSense) — вёрстка уже не мешает игре и чату.

## Общий чат

Кнопка «Общий чат» (справа внизу) доступна на любом экране после входа: в лобби, во время поиска
соперника и прямо в партии. Сообщения видят все подключённые. Это чат «просто поболтать»:
только слова и смайлики. Сервер сам вырезает ссылки, домены, e-mail, телефоны и длинные числа,
оставляя только буквы, простую пунктуацию и эмодзи; максимум 200 символов, не чаще одного сообщения
в 1,2 секунды. Последние 50 сообщений хранятся в памяти сервера (новый игрок видит их при входе)
и пропадают при перезапуске — на диск ничего не пишется. Личный чат с соперником в комнате остаётся
отдельным.

## Реванш

Когда партия закончилась (мат, пат, победа, ничья, потоплен весь флот), под доской появляются
кнопки «Реванш» и «Вернуться в меню игр». Реванш стартует, только когда согласились оба; в реванше
стороны меняются (кто ходил первым, ходит вторым). Если соперник вышел — остаётся только «Вернуться в меню».

## Что исправлено

- **Шахматы и шашки: соперник теперь видит ходы.** Раньше клетка выбранной фигуры сбрасывалась до отправки хода, и сопернику уходил пустой ход. Теперь ход уходит корректно, у обоих игроков подсвечивается последний ход.
- Шашки: в серии взятий нельзя переключиться на другую шашку, у наблюдающего соперника нет лишних подсказок.
- Шахматы: подсветка короля под шахом, убран мёртвый код отрисовки.
- Крестики-нолики 5×5: подсветка последнего хода, защита от некорректных ходов.
- Морской бой: свои корабли видны сразу (кнопка «Перемешать», затем «Готов»); каждый выстрел и результат (попал / мимо / потоплен) виден обоим; потопленный корабль обводится промахами; счётчик оставшихся кораблей; по окончании проигравшему показываются оставшиеся корабли соперника; нельзя выстрелить дважды, пока нет ответа.
- Исправлен атрибут `hidden`: из-за CSS (`display:flex/grid`) скрытые блоки (комната, кнопки реванша, нижняя реклама) не скрывались.
- Из проекта убраны остальные игры (реверси, пять в ряд, нарды, точки, цветные карты, виселица) вместе с переводами и словарным API.

## Известные упрощения

- **Без БД и без валидации ходов на сервере.** Сервер пересылает ходы как есть; клиент соперника
  сверяет ход со своими правилами и нелегальный игнорирует, но полноценного античита нет.
- **Крестики-нолики 5×5**: для победы нужно 3 в ряд (константа `WIN_LEN` в `tictactoe.js`; при 3 в ряд
  первый ход даёт большое преимущество, поэтому стороны меняются в реванше — для баланса можно поставить 4).
- **Шахматы**: пешка всегда превращается в ферзя; ничьей по троекратному повторению и по недостатку
  материала нет (только пат и правило 50 ходов).
- **Морской бой**: расстановка автоматическая (с кнопкой «Перемешать»), ручной нет; попал — стреляешь снова.
- Смена языка прямо в партии не перерисовывает уже нарисованные подписи на доске (косметика).
