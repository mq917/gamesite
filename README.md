# Игра на двоих — битва полов

Сайт для игры вдвоём: без регистрации, подбор соперника противоположного пола
близкого возраста, 10 игр, чат с эмодзи, счётчики онлайн. Вся игровая логика —
на фронтенде (в браузере), сервер только сводит пары и пересылает сообщения.
Никакие данные никуда не сохраняются: ни на диск, ни в базу данных — всё живёт
в оперативной памяти процесса, пока открыта вкладка.

## Структура проекта

```
gamesite/
  server/
    server.js       — весь бэкенд в одном файле (Node.js + ws)
    package.json
  public/
    index.html       — разметка (модалки, лобби, комната игры)
    css/style.css     — вся стилистика, тёмная/светлая тема
    js/app.js          — подключение, лобби, матчмейкинг, чат
    js/games/*.js       — 10 независимых игровых модулей
```

## Как это работает

1. Игрок вводит никнейм, пол и возраст (хранится только в вкладке браузера).
2. Выбирает игру → попадает в очередь ожидания.
3. Сервер ищет в очереди игрока того же game, противоположного пола, с разницей
   в возрасте не больше текущего допуска (±2, увеличивается на 2 каждые 15
   секунд ожидания, до ±20).
4. Обоим показывается карточка друг друга — нужно **обоюдное согласие** («Играть!»),
   иначе (при отказе) сервер запоминает эту пару только в рамках соединения —
   как только вкладка закрывается, все ограничения слетают.
5. После согласия — комната: доска игры + чат. Все ходы и сообщения идут
   через WebSocket, сервер их не понимает и не проверяет, просто пересылает
   второму игроку.

## Запуск локально

```bash
cd server
npm install
npm start
# сайт на http://localhost:3000
```

Откройте два разных браузера/вкладки в режиме инкогнито, чтобы получить два
независимых сеанса и проверить матчмейкинг.

## Деплой в продакшен (бесплатные варианты)

Любой хостинг, поддерживающий длительные Node.js-процессы с WebSocket
(учтите — не подходят чисто статические хостинги вроде GitHub Pages).

### Render.com (проще всего)
1. Залейте папку `gamesite` в свой GitHub-репозиторий.
2. На render.com → New → Web Service → выберите репозиторий.
3. Root Directory: `server`. Build Command: `npm install`. Start Command: `npm start`.
4. Render сам пробросит `PORT` — сервер уже читает `process.env.PORT`.
5. После деплоя сайт будет на `https://ваш-сервис.onrender.com`, WebSocket
   заработает автоматически (Render поддерживает WSS из коробки).

### Railway.app / Fly.io
Аналогично: указываете `server` как корень сборки, команда старта `npm start`.

### Свой VPS
```bash
cd server && npm install
PORT=443 node server.js   # или через pm2 / systemd, за nginx с проксированием WS
```
Не забудьте настроить HTTPS/WSS (например через nginx + certbot), иначе
браузер на HTTPS-странице откажется открывать `ws://` соединение.

## Реклама

Место под баннер — просто `<div class="ad-slot">` сбоку от доски и снизу
страницы (`index.html`). Подключите туда код своей рекламной сети (например
Google AdSense) — вёрстка уже не мешает игре и чату.

## Известные упрощения (осознанные компромиссы MVP)

- **Без БД и без валидации ходов на сервере.** Сервер верит клиенту на слово —
  это даёт максимальную нагрузку на фронтенд и почти нулевую на бэкенд, как и
  требовалось, но теоретически позволяет нечестному игроку с DevTools жульничать.
  Для реального «боевого» уровня античита стоит на следующем этапе продублировать
  проверку правил на сервере.
- **Нарды**: реализован основной цикл (кубики, бар, ходы, взятие «битых» шашек,
  вывод шашек), без редких угловых случаев официальных правил.
- **Карточная игра**: упрощённый Uno — обычные правила смены хода/масти/номинала,
  без «Uno!»-объявления и накопительных стопок +2/+4.
- **Морской бой**: расстановка кораблей только автоматическая (случайная), без
  ручной расстановки.
- **Рокировка/взятие на проходе** в шахматах реализованы; ничья по троекратному
  повторению позиции — нет (только пат и правило 50 ходов).
